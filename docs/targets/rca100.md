# RCA100 / AgenticOpsEval — field contract

> **The richest contract the factory targets.** Six observability modalities, an explicit
> UModel topology, and a four-layer answer key — with **full reference integrity** as a
> hard, enforced invariant.

| | |
| --- | --- |
| Vendor / venue | Alibaba Cloud Tianchi, 2025 |
| Contract version | `v1.1` (`RCA100_CONTRACT_VERSION`) |
| Emitter | [`src/export/rca100.ts`](../../packages/core/src/export/rca100.ts) |
| CLI target id | `rca100` |
| Modalities | metrics, logs, traces, **events**, **alerts**, topology |
| Timezone | canonical UTC ISO-8601 everywhere |

## Why this one is strict

Two facts drive the design:

- **19.4% of upstream root causes are observable only in the Event modality.** Events are
  a first-class citizen, not an afterthought.
- **The official corpus guarantees zero dangling references.** Every `entity_id`,
  `service_name` and `pod_name` resolves into `topology.json`.

The factory enforces rather than repairs: a case whose root cause or whose signals do not
resolve is **skipped with a reason** before a single byte is written.

### Entity resolution order

`resolveSignalEntity` tries the resource attributes most-specific first:

1. `k8s.pod.name`
2. `k8s.node.name`
3. `host.name`
4. `service.name`

and matches each value against `Entity.name` **or any of its aliases**, so the same pod
known as `order-pod-1` in Kubernetes and `svc-order-prod-01` in the CMDB resolves to one
entity.

### UModel type mapping

| IR `EntityKind` | UModel type |
| --- | --- |
| `service` | `apm.service` |
| `pod`, `container` | `k8s.pod` |
| `node`, `host` | `k8s.node` |
| `db` | `apm.external.database` |
| `mq` | `apm.external.message` |
| `cluster` | `k8s.cluster` |
| `external` | `apm.external` |

Several IR kinds collapse onto one UModel type, so `props.original_kind` preserves the
source kind — nothing is lost by the projection.

## Directory layout

```text
cases/
└── {caseId}/
    ├── metrics.json      # entity-aligned long format
    ├── logs.json         # SLS application-log schema
    ├── traces.json       # OpenTelemetry span schema
    ├── events.json       # K8s lifecycle signals
    ├── alerts.json       # entry-alert lifecycle
    ├── task.json         # agent-facing task contract
    └── topology.json     # UModel entity-relation snapshot
answer_key/
└── {caseId}.gt.json      # four-layer ground truth (physically isolated)
```

### `answer_key/{caseId}.gt.json`

Four layers: **outcome** → **reasoning** → **checkpoints** → **⟨comparator, value, unit⟩**.
`raw_ground_truth` is a JSON-encoded string, exactly as the official corpus stores it.

Step roles are derived from position: the first step is `cause`, the last is `impact`,
everything between is `propagation` (a single-step chain is `cause`).

<!-- fields: rca100/answer_key/{caseId}.gt.json -->
| Field | Type | Required | Source (IR) | Notes |
| --- | --- | --- | --- | --- |
| `task_id` | string | yes | `FaultCase.caseId` |  |
| `case_id` | string | yes | `FaultCase.caseId` | Duplicated for downstream convenience. |
| `root_cause_entities[]` | string[] | yes | `Entity.name of rootCauseEntityId` | Empty when the root cause does not resolve (case skipped). |
| `root_cause_types[]` | string[] | yes | `[FaultCase.fault.type]` |  |
| `raw_ground_truth` | string (JSON) | yes | `JSON.stringify({outcome, reasoning})` | Nested JSON string, deliberately not parsed by the exporter. |
| `raw_ground_truth.outcome.target_entities[]` | string[] | yes | `root_cause_entities` | Layer 1: outcome. |
| `raw_ground_truth.reasoning.steps[]` | array | yes | `GroundTruth.causalChain` | Layer 2: reasoning chain. |
| `...steps[].role` | string | yes | `deriveRole(i, total)` | cause (first) \| propagation (middle) \| impact (last). |
| `...steps[].from_entity` | string \| null | yes | `index.byId(fromEntityId).name` |  |

| `...checkpoints[].value` | number \| string | yes | `EvidenceCheckpoint.value` |  |
| `...checkpoints[].unit` | string \| null | yes | `EvidenceCheckpoint.unit` |  |
| `...checkpoints[].description` | string | yes | `EvidenceCheckpoint.description` |  |

## Exporting

```bash
rca-bench export --target rca100 --input examples/order-prod/bundle.json --out-dir ./out
```

Skip policy — enforced **before** any file is written:

| Reason | Meaning |
| --- | --- |
| `no telemetry signals attached` | `bundle.signals[caseId]` is empty |
| `root-cause entity does not resolve into topology` | `groundTruth.rootCauseEntityId` is absent from `graph.entities` |
| `N signal(s) reference entities absent from topology` | `N` signals resolved to nothing; the count tells you how many |

## Scoring

```bash
rca-bench score --target rca100 --dir ./out
```

| Check | What it proves |
| --- | --- |
| `case-present` | at least one case directory was emitted |
| `topology-shape` | `entities`, `edges` and `stats` are present and well typed |
| `entity-refs-resolve` | every `entity_id` in the modality tables exists in the topology |
| `root-cause-resolves` | the answer key's root-cause entity is in the topology |
| `gt-structure` | the answer key has `task_id`, `case_id`, `root_cause_entities`, `root_cause_types` and a parseable `raw_ground_truth` |

The structural check answers *is this well-formed*. Whether it is **scorable** is a
different question, and a different command:

```bash
rca-bench official --target rca100 --dir ./out
```

It runs the published RCA100 protocol (arXiv 2606.29193 §5.4):
`Final_B = (0.4·Entity + 0.3·Fault + 0.3·Process) × 100`. The exported answer key must
score 100; naming a *topologically adjacent* entity earns half credit, and perturbing
the fault type, the causal chain or the observability checkpoints each lowers it.

## Failure modes

| Symptom | Cause | Fix |
| --- | --- | --- |
| `N signal(s) reference entities absent from topology` | the signal's resource attributes do not match any entity name or alias | add the missing name to `Entity.aliases` |
| `root-cause entity does not resolve into topology` | `rootCauseEntityId` typo or missing entity | align the id with `graph.entities[].entityId` |
| `root_cause_entities` is empty | the root cause resolved as `undefined` (case skipped before write) | fix the topology first |
| Everything is skipped | the bundle graph is empty | populate `graph.entities` — RCA100 cannot be exported topology-free |

## Boundaries

- The official distribution serialises the five modality tables as **Parquet**. The
  exporter preserves the identical field contract as JSON so the tables stay diffable and
  byte-stable for Golden-Master verification.
- `first_observed` / `last_observed` are emitted as `null`: the IR does not track entity
  observation windows, and inventing them would be fabrication.
- Profiles are not part of this contract; the IR `profile` signal kind has no RCA100 home.
